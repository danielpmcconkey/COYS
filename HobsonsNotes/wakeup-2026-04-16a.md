## What happened last session

Two infrastructure fixes, both in this session:

### 1. Zazu's Reddit feeds restored

Reddit started returning HTTP 403 to `feedparser`'s default User-Agent.
Both Reddit feeds (general + AI/LLM) were silently returning zero entries.
Nobody noticed because Zazu just reported "no Reddit posts."

**Root cause:** `feedparser.parse()` doesn't raise on HTTP errors — it
returns empty entries with no error field.

**Fix (fetch_rss.py):**
- Added `USER_AGENT` constant with Reddit-compliant UA string.
- Replaced feedparser's built-in fetcher with `urllib.request` (feedparser's
  `agent=` kwarg still gets 403 — it sends extra headers Reddit doesn't like).
- Added HTTP status checking: `urllib.error.HTTPError` caught and surfaced
  as `"error": "HTTP {code}"` in the output JSON. This also caught a
  **second** long-standing silent failure — Reuters' RSS feed is DNS-dead.

**Feed roster change:** Dropped Reuters (dead). Added NPR (`feeds.npr.org`)
and MarketWatch (`feeds.content.dowjones.io`). Updated Zazu's CLAUDE.md
to match.

Yahoo Finance is returning only 1 entry — degrading but not dead. Worth
watching.

### 2. Scotty can now verify Marcus's YouTube token

Scotty was reporting Marcus's YouTube token as "could not read" every
morning because the scotty user had no access to `/home/marcus/.youtube-token`.

**Fix:**
- Added scotty to the `marcus` group (`sudo usermod -aG marcus scotty`).
- Changed `agents/marcus/scripts/auth.py` chmod from `0o600` to `0o640` so
  the group-readable mode survives token refreshes.
- Dan ran `sudo chmod 640 /home/marcus/.youtube-token` for the live file.
- Improved error diagnostics in `run_health_check.py` — token check now
  distinguishes "file not found" / "permission denied" / "read error" /
  "OAuth failure" instead of one generic message.
- Verified: scotty user gets `{"valid": true, "level": "green"}`.
