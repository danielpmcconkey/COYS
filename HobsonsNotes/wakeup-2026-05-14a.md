### The diagnosis

### What OpenClaw was doing

Single Node process (`/usr/bin/node /usr/lib/node_modules/openclaw/dist/index.js gateway`)
that did three things at once:

1. Held Discord gateway connections for every bot account, including
   `main` (= original Zazu, channel `1476537750239973482` = #morning-report).
   Tokens were in `~/.openclaw/openclaw.json`.
2. Ran cron jobs from `~/.openclaw/cron/jobs.json`: Bede `0 0,2,4 * * *`,
   Marcus `0 17 * * *`, Scotty `0 6 * * *` — same schedule as their COYS
   counterparts. State file confirmed all three had run yesterday/today.
3. Brokered Claude API calls on localhost:18789.

So Bede/Marcus/Scotty were **double-running** since the reboot, and Zazu
was effectively running twice (whichever process held the Discord
connection at moment of @-mention "won" the message). The bad-Zazu
report was the OpenClaw `main` agent — older config, weaker rules, no
angle-bracket discipline, fabrication-prone.

## Standing corrections

- **"Stopped" is not "disabled."** User-systemd services with
  `WantedBy=default.target` survive reboot if disable was skipped. When
  retiring any background service in future, the dance is
  stop → disable → mask → remove unit file → remove data → uninstall
  binary. Verify with `systemctl --user list-units --all | grep` AND
  `pgrep -af`. Not just `systemctl status` (gives "not loaded" for
  user units when run system-wide).
- **`/home/{agent}/` is not the agent's working directory.** The
  personality CLAUDE.md lives in `/media/dan/fdrive/codeprojects/COYS/agents/{agent}/`.
  When testing an agent interactively via `sudo -iu {agent} claude`,
  cd into the agent dir first or claude finds no project context and
  falls back to generic personality.
- Scotty's and Marcus's CLAUDE.md tell them scripts are "ALREADY BUILT.
  Do NOT create, modify, or debug it." This is agent-persona guidance.
  Hobson (infrastructure maintainer) can and should edit scripts when
  fixing cross-agent issues — but be explicit with Dan about what
  you're touching.
